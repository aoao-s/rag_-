## 判据可达性

- 全网格（三套 margin 空间 × 81 个阈值）在 test 上的最好精度：**1.000**（召回 0.127，`normalized` / 0.54 / 0.22）
- 精度 0.95 可达，但代价是召回只剩 0.127——特征能分开的只有最干净的那一小撮；召回要到 0.637 时精度上界见「反向选点」。两根旋钮（threshold + margin）到此为止，把剩下的区间交给下一阶段的机制（三档路由）。

## 结论

**样本来源为 `source=rule`（规则改写），结论只能算临时值。**
规则变体的词面偏离比真实口语小，分数分布偏高，标出来的阈值会偏保守（宁可漏答）；
拿到生成模型密钥后必须重跑 `gen --source llm` + `calibrate`，才可作为改写线上默认参数的依据。

- 本次 dev 选点（`normalized` / 0.61 / 0.04）在独立 test 上的精度：0.872、召回 0.134 → **未通过** §7.1.7 第三步验收（precision ≥0.95 且 recall ≥0.637）。
- **不建议据此改动线上参数**：dev 上过闸、test 上不过。dev 只有 581 条负样本，一条就是 0.17 个百分点精度；test 只有 259 条，一条是 0.39 个百分点——精度 0.95 这道闸门在两个集合上都贴着噪声，选点落在边界上就会翻。
- 反向问法给出的上界：把召回守在现基线 0.637，dev 上能选到的最好精度是 0.827（test 0.810）。两根旋钮（threshold + margin）到此为止——要精度只能把召回砍到 0.1 量级。
- 现行默认（`normalized` / 0.25 / 0.10）在 test 上是召回 0.382、精度 0.775，本身已落在前沿上，继续调参没有真实的收益空间。
- 按召回目标 0.70 反过来选 margin：`normalized` 下最紧能收到 0.02（test 召回 0.748、精度 0.627）——就在这个点上精度也只有 0.627，离 0.95 还差得远；精度与召回在这套特征上此消彼长，不存在两者同时达标的点。
- 分数分辨力不足：正样本 p90 0.652 / max 0.733，负样本 p90 0.516 / max 0.752——负样本的高分尾部伸进正样本主体里，单一阈值只能二选一。
- 长查询靠词数堆分：`21–40` 字区间负样本误命中率 0.273、正样本召回却只有 0.267（见长度切片）——同一区间两头都变差：BM25 原始分随命中词数增长，`score_norm` 只是单调压缩，分不清"题干里出现这些词"与"问的就是这件事"。
- 阈值在 0.10–0.35 完全不生效（召回 0.382 / 精度 0.775 一模一样）：真正卡住命中是 margin 0.10，不是 threshold——"调阈值"这条路上本来就没有空间。
- 判定里没有任何"查询形态"信号（概念题 / 选择题 / 计算题），也拿不到同题族结构；只用（分数 + margin + 候选数）这些特征时，上面就是精度上界。
- 下一步（对应 §7.1.7 第四、六步）：三档路由把中置信命中交 RAG 并附 top3 候选，而不是直接答——那才是消化这段"答不准"区间的正确位置；若要让 FAQ 自己扛住精度，得先有查询形态信号（或用学科内同题族做二次判别）。

选点原则：FAQ 答错（把 A 的答案给 B）比不答更伤信任，不答还能交棒 RAG。
因此先卡精度 ≥0.95，再最大化召回；margin 是在同题族（内容 / 证明 / 应用）之间保命的旋钮。
